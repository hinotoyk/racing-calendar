## 1. 方案定稿

**一个组件文件 + 各站一行挂载点**：`friend-links.js`（零依赖、无构建要求、自渲染自样式），
四站各放一份**完全相同**的副本；站点清单（名称/logo/品牌色/URL/一句话简介）内嵌在文件头
`SITES` 注册表里 —— **增删站点或改文案，四站副本同步改**（这是本方案唯一的同步成本）。

每个站在页面里放一个挂载点声明自己的身份与皮肤，脚本按 `data-site` **排除自身**、渲染其余三站：

```html
<div data-friend-links data-site="yunji" data-skin="yj"></div>
<script src="friend-links.js" defer></script>
```

**设计语言（signature）**：每个站用它呈现自己的方式被呈现 —— 汉字/字母品牌方块
（雲 / 絆 / LS / RC，四块统一家族青绿 `#0aa7a0`；LS = Leading Sire，jbis 站的排名主题；
RC = Racing Calendar）+ 站名 + 一句话简介。四块同色是刻意的：同一家族的姊妹站，家族色即识别色。

**组标题（2026-10-23 用户定稿）**：「站群导航 · NETWORK」—— 四站既有档案也有榜单与工具，
「站群导航」比「档案/友链」更涵盖全部（曾候选：友情档案 / 姊妹站 / 家族站 / 马房等，均未采纳）。

展示名（2026-10-22/23 定稿）：云迹 · 云崽档案 / **絆 · 绊崽档案** / **JBIS LS Rank榜** /
**Racing Calendar**（jbis/rc 用短拉丁名，与 LS/RC 方块呼应，窄列不截断）。

## 2. 各站挂载位置与皮肤

| 站点 | 挂载位置 | 皮肤 | 样式来源 |
|---|---|---|---|
| yunji | `front/index.html` 侧栏 nav 之后、版权块之前（桌面常驻 + 手机抽屉内） | `yj` | Tailwind utility 字面量，写在 JS 里（两站 `tailwind.config.js` 的 content 扫 public 目录 → 编译进 theme css；改类名后照常 build + 核对 dist） |
| kzn | 同 yunji（同一模板） | `yj` | 同上 |
| jbis | `site/index.html` 明細表（main）之后、colophon footer 之前 —— **页脚收尾区**：读完内容自然到达的出口，不占首屏、不混入站头功能区 | `jbis` | jbis 系皮肤（jbis / rc 两站共用），运行时注入自带 CSS，颜色经**归一化变量**取宿主 token |
| rc | `site/index.html` 明細表（`#pager-mount`）之后、colophon footer 之前 —— 同 jbis 的页脚收尾区 | `jbis` | 同上 |

- `yj` 皮肤视觉 = 侧栏既有元素逐类复用：分组标题与 nav 组标签（「统计」）同款，条目与
  `nav-item` 同款（`hover:bg-muted/40`），品牌方块为品牌区 logo 同构（26px 缩号）。
- `jbis` 系皮肤视觉（v2 定稿）= 宿主 panel 同语言：白底细线 8px 圆角卡片、自适应列宽
  （`repeat(auto-fit,minmax(280px,1fr))`，2~3 张卡自动分行），标题 = 中文粗题 + 英文小字副题
  「NETWORK」，条目 hover 同表格行（浅底 + 品牌边 + ↗ 现形）。
- **归一化变量**（一套 CSS 双站兼容的关键）：注入 CSS 先在容器上定义
  `--f-line: var(--line, var(--border, #e5e5e5))`、`--f-muted: var(--muted-foreground, var(--muted, #737373))`、
  `--f-accent: var(--primary, var(--accent, #0aa7a0))`、`--f-accent-soft: var(--accent-soft, var(--accent, #e6f6f5))`、
  `--f-ink: var(--ink, var(--foreground, #1a1a1a))`、`--f-card: var(--card, #ffffff)`；
  jbis 原生变量（`--line/--muted/--accent/--accent-soft/--ink`）与 shadcn 风（rc：
  `--border/--muted-foreground/--primary/--foreground/--accent`）经 fallback 链自动各取所需。
  ⚠ 变量名语义冲突警示：rc 的 `--muted` 是**浅灰底**、`--accent` 是**浅青底**（与 jbis 的
  前景色语义相反）—— 归一化链的顺序专门为此设计（rc 走 `--muted-foreground`/`--primary`）。
- 环境色跟随宿主主题（jbis 的 mint/mist/ink/sand 换肤自动跟随）、品牌色（logo 方块）恒定。

## 3. 交互语义

- **一律新标签页**（`target="_blank" rel="noopener"`）：四站都是带页内状态的查询工具
  （筛选/图表选择/页码/勾选），跳走不丢状态；外站也不进本站 iframe。
- 展示名规则：站名 + 副题连写 ≤10 字才拼「name · sub」（云迹 · 云崽档案 / 絆 · 绊崽档案），
  JBIS LS Rank榜 / Racing Calendar（无副题）单显 —— 侧栏窄列不截断。
- 可访问性：装饰元素（logo 方块/箭头）`aria-hidden`；卡片有 `:focus-visible` 描边
  （与宿主焦点语言一致）；动效仅颜色/透明度过渡，尊重 `prefers-reduced-motion`。
- 容错：挂载点本身不带任何样式类，脚本缺失/渲染异常时**零痕迹**（不出现孤立分隔线或空占位）。

## 4. 缓存与版本

- yunji / kzn：`front/public/friend-links.js` 由 Vite 原样拷到 dist 根；页面引用
  `<script src="friend-links.js" defer>` 由构建期 `auto-version` 插件自动打内容哈希戳
  （内容变 → URL 变 → 缓存自动换新）。
- jbis / rc：`site/friend-links.js` 由各自构建脚本整目录拷进 `_site/`（jbis `src/build-site.js`、
  rc `src/build.js`）；GitHub Pages 缓存 ~10 分钟，无版本戳（与站点其余静态资源口径一致）。
- 日常数据构建（各站照常 build）自动携带最新组件，无需额外步骤。

## 5. 维护手册（唯一要做的事）

1. **增删站点 / 改文案 / 改 URL**：改 `friend-links.js` 头部 `SITES` 注册表 → 同步覆盖
   四站副本（yunji `front/public/`、kzn `front/public/`、jbis `site/`、rc `site/`）→ 各站照常构建。
   新站如无对应皮肤，用 `data-skin="yj"` 或 `"jbis"` 里观感更接近的一种即可（jbis 系新站若
   变量命名也不同，往归一化 fallback 链里补一层即可，皮肤 CSS 零改动）。
2. **新站接入**：在站内放挂载点（选一个页面常驻区域）+ 引脚本 + `data-site` 填新站 id
   （与注册表一致才会正确排除自身）。
3. **不要**把友情入口做成站内 iframe 加载外站（本方案用新标签页，见 §3）。

## 7. 已知取舍

- 友情入口在模板站位于侧栏底部（信息层级低但常驻可见）、jbis/rc 位于页脚收尾区（不抢首屏、
  读完内容自然到达）。jbis v1 曾放站头 tabs 下方，实测混入功能区观感杂乱，已废弃；
  若日后想提高某站入口层级，把挂载点 div 移到常驻头部即可，组件零改动。
- 四站副本同步是手工约定；若站点数量继续变多，可再升级为「单点托管 + 其余站外链加载」，
  当前 4 站规模下本地副本更稳（无跨域单点依赖，file:// 本地预览也可用）。
