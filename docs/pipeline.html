② 日本源：JBIS 三级抓取

Step 1 · 赛历 jbis.or.jpparseCalendar()

https://www.jbis.or.jp/race/calendar/?year={Y}&month={M}

得到字段：{ date, track(3位场码), scope(central|local), gradeTag } —— 正则抓 li.calendar__track-1|2 内的 a[href=/race/calendar/YYYYMMDD/CCC/]。

清洗：同一 date+track 去重；track-1 = 中央、track-2 = 地方。 场码经 src/race-config.js → VENUES 映射出场名（236=門別、220=大井、105=東京…）， 未知场码按数值段推断（<200 中央）。

落盘：data/races/_calendar/{YYYY-MM}.json（schema jbis.race.calendar/v1）。

Step 2 · 当日页 jbis.or.jpparseDayPage()

https://www.jbis.or.jp/race/calendar/{YYYYMMDD}/{CCC}/

解析方式：JBIS 全站为 div 嵌套布局（非 table）。按顶层 <div> 深度切分定位数据块： 中央认 div.data-6-12、地方认 div.data-6-35；表头文字定位列序，逐行切格。

得到字段：R号、発走时刻、比赛名、芝/ダ/障、距離(m)、頭数、gradeTag、raceKey（YYYYMMDD/CCC/RR）。

清洗：

  • 比赛名先过 normalize()：全角数字→半角、ⅠⅡⅢ→1/2/3、压缩空白；
  • 再过 klassOf() 归一为展示用「比赛格」：重賞系（GⅠ-Ⅲ / JpnⅠ-Ⅲ / JG / 準重賞）、新馬 / 未勝利 / 1-3勝クラス、地方班级 A1-C3（取首个班）、特選 / 交流 / 一般，并归入 klassGroup 粗分组；
  • 状态判定：頭数未出 → pending；勝馬列为「-」/空 → entries（要采出馬表）；已有胜马 → result。

Step 3 · 出馬表 jbis.or.jpparseEntryPage() / parseRunner()

https://www.jbis.or.jp/race/{YYYYMMDD}/{CCC}/{RR}/　（RR 补零；404/非出馬表时回退 /race/result/… 再试一次）

解析方式：认 div.data-6-27 块；严格按表头文字定位列 （枠〔中央写「枠番」地方可能只写「枠」〕/馬番/競走馬名/性齢/騎手/指数/調教師/1-3走前）—— 未確定页可能整列缺失，绝不按位置猜列。

得到字段（每马一行）：

字段内容清洗规则
frame / num枠番 / 馬番只认表头列，值「--」或未公開存 null，UI 显示空，不猜
horse{id(10位), name}只取出 10 位 id；马名不用表内文本，改由马页权威化（见 ②-b，避免「 B」装备标记 / 国名括注尾缀误伤）
sex / age性齢先匹配「セン」再匹配单字「セ」（顺序错则骟马整条失败）
color毛色同一格内 13 种固定毛色词（黒鹿毛/青鹿毛/鹿毛/栗毛/青毛/芦毛/白毛/粕毛/月毛/桃毛/河原毛/駁毛/不正毛）
jockey + weight騎手 / 斤量骑手 id 从链接；斤量正则 \d{2,3}(\.\d)?
trainer / belongs調教師 / 所属所属取链接后 (…) 括注
owner / breeder馬主 / 生産者id+name，供彩衣链路用

②-b 马名权威化 jbis.or.jp/horseparseHorseProfile() / resolveJbisName()

https://www.jbis.or.jp/horse/{10位id}/　（缓存 data/pedigree/jbis-name.json）

为什么：出馬表马名是显示名，带装备标记「 B」（ブリンカー，190 例）和国名括注「(USA)」（141 例）。 靠正则剥尾缀会误伤纯 ASCII 名（如 Indy B 的 B 就是名字本身）。改为「只认 id，登录名从马页读」。

  • 日文名 ← <div class="hdg1-search"><h1>（如 エアジーン）；纯英文名马匹 h1 亦为 ASCII → 判定为无名日文名，只存英文名；
  • 英文名 + 国籍 ← <span class="hdg1-search__sub">Air Gene(JPN)</span>，拆成 en="Air Gene" / country="JPN"；
  • 生日 ← <dt>生年月日</dt>（精确到日），是彩衣唯一性判定的最佳依据（优于「赛事年 − age」）；
  • 落盘字段：horse.name（日文名，无则英文名）、horse.nameJp、horse.nameEn、horse.country、horse.foaled；
  • 缓存键 = JBIS 10 位 id，含 {miss:1} 终态；重跑 0 网络。
抓取约束：JBIS 对本机 IP 有 WAF 限流（短时高频 → 整站 403，持续数分钟至数十分钟）。 因此马页抓取默认 单并发 + 3.5s 间隔，遇 403 不写缓存、暂停 2 分钟，连续多次则停批（缓存已存，重跑续采）。 马页需要接近真实浏览器的完整请求头（Accept-Language / Sec-Fetch-* / Referer）。

③ 欧美源：Racing Post（抓取层 Sporting Life）

为什么不是 racingpost.com？ RP 官站 WAF 对一切非浏览器客户端返回 406（页面与 /api/* 同样拦截）。 RP 集团旗下 sportinglife.com 提供同源 racecard 数据且 robots.txt 无任何 Disallow， 因此以 SL 为抓取层、按 RP 口径映射；RP 直连探测保留在 probe()，日后解封可直接切换。

Step 1 · 当日 index sportinglife.comcollect() → meetings

https://www.sportinglife.com/racing/racecards

解析方式：Next.js 站点，从 HTML 内嵌 <script id="__NEXT_DATA__"> 提取 JSON （sources/http.js → nextData()），取 props.pageProps.meetings。 同时从 <a href> 收集「race id → 单场路径」映射表（Next 路由需要）。

会议过滤：meeting_summary.course.country.short_name 按 COUNTRY_GROUP 折算（GB = ENG+Wale+SCO；IRE = Eire；另有 FR / UAE / SAF / USA / CAN）， 支持 --countries all 全量或 --tracks 指定课程。

Step 2 · 单场 racecard sportinglife.comrunnerOf()

https://www.sportinglife.com/racing/racecards/{date}/{course}/racecard/{raceId}/{slug}

解析方式：同样提取 __NEXT_DATA__，取 props.pageProps.race.rides（出走数组，逐 ride 映射为 canonical runner）。

Step 3 · 马匹档案（父/母/母父） sportinglife.compedigreeOf()

https://www.sportinglife.com/racing/profiles/horse/{horseId}

同样 __NEXT_DATA__ → profile，取 sire.name / dam.name / damsire.name / colour / sex / foaled， 缓存入 data/pedigree/rp-horse.json（pedCache 单文件包，CI 增量复用）。

父父补全（关键设计）：SL 的父系引用 id 缺陷导致无法链查父父， enrichSireSire() 借道 JBIS 馬検索：把本场合计的父名/母父名收集去重 → lib/horse-lookup.js 解析为 JBIS id（缓存 data/pedigree/name-lookup.json， 现役种公马别名由 jbis-sire.json 预置，防同名老马错绑）→ 行内有「父」列时补 sireSire = {id, name}。 这些解析记录同时也是 build 侧马名别名字典的数据源。

彩衣 · 直接来自 racecard sportinglife.comslSilk()

https://www.sportinglife.com/images/silks/{silk_filename}　（208×150 PNG）
  • SL 单场 racecard 的 __NEXT_DATA__ 每个 ride 自带 silk_filename（如 20261104mus131001.png），无需二次查询；
  • 文件名为「日期+场地+场次+馬番」组合 → 按内容 sha1 去重落盘 data/silks/sl-{hash}.png（同一马主跨场同图只存一份）；
  • 缓存 data/pedigree/sl-silk.json（filename → colours / miss），重采 0 请求；
  • runner 挂 silk = { url, owner:{name}, via:"sportinglife" }，与日本源同一展示口径。

时区与比赛日（欧美源最易错处） normalize.js 头注

  • SL 页面 time 一律是英国当地时间（Europe/London），与场地所在国无关（实测 Abu Dhabi 13:00 = 当地 17:00，Belmont 17:10 = 当地 12:10）；
  • date 是场地当地比赛日标签 —— 美国夜场跨英国午夜仍属同一比赛日；
  • 落盘双口径：timeZone（展示口径，RP 恒 Europe/London）、localTimeZone（场地时区，date 标签口径，COURSE_TZ 表 + 个别场地 override）、startTimeInstant（ISO8601 绝对时刻）；
  • raceInstant() 用场地时区反推消解跨日歧义：对 date 标签试 shift 0/1 天，哪个解释与标签自洽取哪个（DST 用两步校正法处理）；
  • build.js 据此给 RP 行补北京时间（Asia/Tokyo 展示口径），与 JBIS 行同列展示。

比赛格归一（RP 口径）klassOfRP() / runTypeOf()

  • 赛名 Group 1-3 / Grade 1-3 → GⅠ-GⅢ、Listed → L，group=重賞；
  • runTypeOf() 由赛名推断竞走种别：steeple/chase → CHASE、hurdle → HURDLE、nh flat/bumper → NH_FLAT、其余 FLAT；
  • HURDLE/CHASE → group=障害；其余 Class 1-7 → klass="Class N"（group=一般/障害）；
  • 场地：surfaceOf() TURF→芝、all-weather/fibre/polytrack/sand/tapeta→ダ（英国全场地按惯例归ダート）。

④ 彩衣（勝負服）富化 —— netkeiba 优先 → winfinal 兜底

语义前提：彩衣属马主而非骑手/马，因此链路终点是「马主 → 彩衣图」。 日本源（JBIS）全站无彩衣；按「马名 + 生年」两个来源依次确认唯一性： netkeiba（覆盖最广）→ 未命中走 winfinal 勝負服データベース。 欧美源不在此链路，彩衣直接取自 Sporting Life racecard（见 ③）。

捷径 · NAR 出馬表（地方限定）enrichSilks() / parseNkShutuba()

https://nar.netkeiba.com/race/shutuba.html?race_id=YYYY+jyo+MMDD+RR

地方 race_id 可由日期直构（JBIS 场码 → netkeiba jyo_cd 映射表 NK_JYO：門別=30、大井=44、園田=50…）； 中央 race_id 含開催回次/日次，无法由日期推出 → 走兜底。解析 <a id="umalink_{nkId}"> 得「归一马名 → nk 马号」映射。

兜底 · 马名搜索（中央 / 未命中）resolveNkIdByName()

https://db.netkeiba.com/horse/ajax_horse_search.html?func=whole&word={EUC-JP编码}&match=b&limit=10
  • EUC-JP 编码：db.* 全站 EUC-JP，word 必须 EUC-JP 百分号编码；Node 无对应 Encoder， lib/silks.js → eucJpEncode() 用 TextDecoder 一次性建 JIS X 0208 反查表（≈3.5k 项）实现零依赖编码；
  • 防同名错配：搜索行带生年，用「赛事年 − age」反推出生年双匹配；同年仍多条 → 写 miss 终态；
  • 搜索行同时带出 owner id（/owner/race.html?id= title=马主名）→ 后续无需访问马页。

兜底 · winfinal 勝負服データベース fuku.winfinal.comresolveWfSilk()

https://fuku.winfinal.com/?action=horse_name&q={馬名}　（馬名完全一致検索）
  • netkeiba 判无（搜索 0 命中 / 马主未登记 / 双 404）后启用；覆盖 netkeiba 未登记的地方马主、外国产马；
  • 结果卡含 馬名 / 英字 / 性・毛色 / 生年月日 / 馬主名 / 服色图 六项；
  • 唯一性判定：馬名归一后完全一致 + 生年月日年份一致（生年来自 JBIS 马页 foaled）；命中多条或 0 条 → 记 miss，不猜；
  • 服色图 img/{xxxx}.gif → data/silks/wf-{xxxx}.gif；同一马主多马共用一张图（wf-owner 缓存）；
  • 缓存 data/pedigree/wf-horse.json（馬名|生年）与 wf-owner.json（馬主名）。

归一与缓存nkNameKey() / nkOwnerKey() / nkMap / nkOwner

  • 马名归一 nkNameKey()：去空白、剥国名括注 (USA) 等、剥装备标记「 B」尾缀 （ブリンカー等，仅 JBIS 出马表显示用；仅当主体含假名/汉字才剥，纯 ASCII 外语名的字母可能是真名）。 循环剥到稳定，处理叠加尾缀如「ディープスリー(USA) B」；
  • 马主名归一 nkOwnerKey()：全角→半角、去空白、去法人括注 (株)/(有)/(同) 等、大写化 —— JBIS 与 netkeiba 写法差异的对齐键；
  • 缓存体系（data/pedigree/，入库供 CI 增量复用）： nk-owner-v3.json（key=netkeibaId，马主级 · 同马主多马 0 请求）、 nk-map.json（key=归一马名|出生年，搜索结果终态）、 nk-horse.json（旧链路，保留供回溯）。

彩衣图下载 · URL 直构downloadSilkByOwner()

https://cdnv2.netkeiba.com/img/db/colours/{ownerId}.{png|gif}
  • png 为 320×240 高清版（gif 仅 73×55），png 优先；
  • 无彩衣马主两个扩展名均 404 → 终态可判定，写 miss 缓存不再重试；
  • 图落 data/silks/{ownerId}.{gif|png}（马主去重，本地存在即复用）， runner 挂 silk = { url: "data/silks/…", owner: {id, name} }，幂等指纹纳入 silk.url；
  • owner id 无线索时按马主名搜 db.netkeiba.com/owner/list.html?word=（EUC-JP）→ canonical 页取数字 id；首搜无结果时剥英文尾缀重试（JBIS 法人名常带 R/HD 等尾巴而 netkeiba 不带）。

现状覆盖：全量 v3 回填 63 场 7700 马次挂彩衣 4071（52.9%）； 未覆盖主因 = 地方马主在 netkeiba 未登记服色（数据源上限，非映射 bug）。

⑤ 血统补全（两源各自的路径）

JBIS 源enrichPedigree() / parsePedigree()

https://www.jbis.or.jp/horse/{10位id}/
  • 出馬表已带父/母/母父，直接用；
  • 缺「父父」→ 查种马缓存 jbis-sire.json，未命中抓父马页（resolveSireSire）；
  • 缺母父/母 → 抓本马页，血统区六格按序取（父父/父/母父之母 / 母/母父/母之母）；
  • 顺带取官方英文名 nameEn（hdg1-search__sub），作片假名↔英文归一的桥；
  • 两级缓存 jbis-sire.json / jbis-horse.json，CI 增量复用。

RP 源pedigreeOf() / enrichSireSire()

https://www.sportinglife.com/racing/profiles/horse/{id}
  • 每马一次档案抓取补父/母/母父（纯名字，id 缺陷见 ③）；
  • 父父借道 JBIS 馬検索按名字解析（name-lookup 缓存 + 现役种公马别名预置）；
  • CI 日常 overwrite=false 只填空值；--revalidate 模式可覆盖修正错绑。

幂等规则（两源同款）

  • 指纹幂等：赛事数 / 头数 / 马ID:番号（JBIS 额外含 枠番·性齢·彩衣URL）全一致 → 跳过不写； 枠順更新、性齢修正、彩衣补全会触发重写；
  • 防截断：--limit / --tracks / --dates 部分采集时，已存文档头数更多则不覆盖；
  • 彩衣继承：采集重建 runner 时按 (raceNo, horseId) 继承已有彩衣（inheritSilk），防止把回填结果冲掉；
  • 旧明文迁移：兼容读 .json，写后删除旧明文，统一 gzip。

⑦ 合并与展示（build.js → _site）

  • 合并：遍历 data/races/ 全部文档，sourceOf() 区分 jbis / racingpost （v1 卡片 source 字段是 URL → 视为 jbis）；
  • 行级展开：rowOf() 把 runner 压成行（含 source、彩衣根相对路径 silk 字段）， rows-codec 自描述 schema 字典包编码 → _site/derived/*.json；
  • 来源口径：RP 行的筛选口径按国家组（countryGroupOf：ENG/Wale/SCO→GB…）， 日本行按场馆名单分 JRA / NAR；
  • 北京时间：JBIS 行（Asia/Tokyo）与 RP 行（Europe/London 展示口径 + 场地当地）统一补北京时间列，同日并列展示；
  • 别名字典：RP 父父解析记录并入 derived/horse-aliases.json（片假名↔英文名互查）；
  • 静态资源：data/silks 复制进 _site/data/silks；rows-codec 编解码模块复制进站点供前端解包；
  • 前端：site/app.js 拉取 derived 字典包解包渲染，出馬表 silk 列（懒加载 + 404 隐藏）、 分享卡双版式、每周 Excel（_site/excel/）。

⑧ 抓取纪律与 CI 调度

JBIS / fetch.js

  • 诚实 UA：Mozilla/5.0 (compatible; JBIS-Race-Calendar/1.0; personal research, polite crawl)；
  • DELAY_MS 礼貌间隔（config.delayMs）；

netkeiba / RP

  • 均需浏览器 UA（bot UA 拿不到正文 / RP 直接 406）；
